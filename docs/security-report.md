# סקירת אבטחה — מעגל מכירות

המערכת מדגימה הגנה בשכבות, הצפנת שדות AES-256-GCM, אימות בקשות HMAC, RBAC, CSRF, prepared statements, פלט מבוסס מקור, הסגר וראיות. בדיקות קוד ודמו אינן בדיקת חדירה עצמאית או הסמכת אבטחה. גבולות אלו הם תנאי No-Go לשימוש בנתונים אמיתיים עד טיפול.

## S01 — גבוהה: מפתח פענוח נמצא באותו מחשב

data/vault.key מוגן ב-Windows ACL ונפרד מהקוד. מי שמשיג גישה מלאה לחשבון המפעיל יכול להשיג גם נתונים וגם מפתח. לפני Production: KMS/HSM, רוטציה, הפרדת הרשאות וגיבויים מוצפנים. נתוני מטא-דאטה תפעוליים כגון timestamp, status ותפקיד נשארים נגישים למסד לצורך חיפוש; השדות הרגישים עצמם מוצפנים.

## S02 — גבוהה: שני חשבונות דמו ללא SSO/MFA

הקודים אקראיים וארוכים, תפקידי מנהל/מכירות נפרדים והסגר פועל לפי זהות החשבון. אין שיוך אוטומטי לאנשים אמיתיים בארגון. לפני Production נדרשים IdP ארגוני, MFA, RBAC לכל משתמש ומנגנון break-glass מבוקר. אין להסיק זהות אדם מ-IP בלבד.

## S03 — גבוהה: תשתית דמו תלויה במחשב ובמנהרה זמנית

Vercel מספק את הממשק וה-Gateway; המודל והמסד נמצאים בשרת המקומי. נפילת המחשב/מנהרה משביתה פעולות. אין התחייבות לזמינות Production. יש להעביר לשרת מנוהל, named tunnel או רשת פרטית, health checks, גיבוי ושחזור בדוק.

## S04 — בינונית: שלמות לוגים ללא עיגון חיצוני

שרשרת HMAC מזהה שינוי או שיבוש באמצע הרשומות. מחיקה של סוף השרשרת אינה ניתנת לגילוי בלי anchor חיצוני; מפתח שנגנב מאפשר זיוף. לפני Production יש לייצא עוגנים חתומים ל-WORM/SIEM עם retention ומפתח נפרד. אין לכנות את הלוג "בלתי ניתן לשינוי".

## S05 — בינונית: כללי זיהוי הזרקה אינם מכסים כל נוסח

יש נרמול Unicode/URL, דפוסי הזרקה, בדיקת סכמות, ציטוט מקור, כלי שרת בלבד ואישורי אדם. prepared statements מונעים ביצוע SQL גם כשדפוס זיהוי אינו מזהה את התקיפה. אין טענה שכל prompt injection מזוהה. הוספת ניסויי red-team רב לשוניים ו-KB poisoning היא משימת שיפור רציפה.

## S06 — בינונית: צילום הוא ראיית לקוח מסייעת

html2canvas מצלם את חלון האפליקציה, אינו מצלם את כל המחשב, ויכול להיכשל או להיות מזויף על ידי תוקף. השרת מצפין ומחשב hash לתמונה; לא ניתן להסיק מה-hash שהתוכן אמיתי. הראיה הסמכותית היא אירוע השרת עם זמן/runId ונתוני הבקשה המצונזרים. גישת תמונות מורשית למנהל בלבד.

## S07 — בינונית: התראות חיצוניות אינן מוגדרות

התראות, שיוך והסלמה פועלים במרכז הפנימי. אין יעד דואר/Slack/Teams או שרשרת אנשי קשר שהוגדרו; לא נשלח דבר מחוץ למערכת. לפני הפיילוט נדרשים יעדים, delivery acknowledgments, retry queue ו-on-call escalation לפי SLA.

## S08 — בינונית: DLP, עומס והגנות תשתית

הצנזור מסיר דוא״ל, טלפון ישראלי, רצפי ספרות וסודות מסוג sk-. הוא אינו מסווג כל פרט רפואי, סוד או PII. יש קצב בקשות ומגבלת קריאות AI, אך אין WAF/Redis ארגוני משותף. יש להגביל שימוש בדמו לנתונים סינתטיים; לפני Production נדרשים DLP, quotas, בקרת disk growth, retention, עומס והתאוששות.

## בדיקה יזומה והרשאות

הדמו אינו מפעיל SQL מהקלט, shell מהקלט או כלי שליחה. Gateway מקבל נתיב API מוגבל בלבד, משתמש בסוד צד שרת ובחתימה עם nonce וזמן, ואינו מאפשר URL שרירותי (מניעת SSRF). יש בדיקת מקור, cookie HttpOnly/SameSite ו-Secure בענן, CSRF לכל שינוי, CSP והצגת קלט דרך textContent. ניסיונות התחברות ושגיאות נרשמים ללא סודות. רוטציה וניתוק מהירים נדרשים אם URL או קוד גישה דולפים.
