# מעגל מכירות

סוכן AI פנימי לצוות מכירות. הוא הופך הערות משיחת מכירה לסיכום מצוטט, למשימת המשך ולטיוטת מייל, ומשפר את בסיס הידע בכל פעם שעולה שאלה שאין לה תשובה. ה-AI רק מציע. אדם מאשר כל דבר.

פרויקט גמר בקורס AI, שילוב רעיונות 9 ו-10 מתוך דף המטלה. מגיש: עופר שחר.

**המערכת החיה:** https://sales-knowledge-ofer.vercel.app
(הכניסה בקוד גישה אישי שמתקבל מעופר)

---

## מה המערכת עושה

**מעגל המכירה (רעיון 9)**
הערות שיחה ← בדיקת קלט וזיהוי הזרקות ← המודל בוחר ציטוטים ← השרת מאמת כל ציטוט מול ההערות ← משימה וטיוטת מייל ← מנהל מאשר ← ייצוא קובץ מייל

**מעגל הידע (רעיון 10)**
שאלה בלי תשובה מאושרת ← כרטיס "ידע חסר" ← קיבוץ לפי נושא וספירת חזרות, כולל רשימת כל השיחות שבהן חסר המידע ← מנהל מציע תשובה עם מקור ומאשר ← בדיקה שהתשובה החדשה לא משנה תשובה קיימת ← הסוכן עונה ממנה מעכשיו

**מסכים:** שיחת מכירה, בסיס ידע ופערים (כולל ייצוא לאקסל), מרכז אישורים, דשבורד, אבטחה והתראות, יומן ביקורת, צ׳קליסט הגשה, חיבור מודל.

## הרצה מקומית

לא צריך מסד נתונים ולא צריך מפתחות. נדרש Node בגרסה 22 ומעלה.

```bash
git clone https://github.com/OFFERSHAHAR/sales-knowledge-cloud.git
```
```bash
cd sales-knowledge-cloud
```
```bash
npm install
```
```bash
npm start
```

פותחים בדפדפן את הכתובת:
```
http://127.0.0.1:8765
```

קודי הכניסה המקומיים נוצרים אוטומטית בקובץ:
```
data/local-keys.json
```
בוחרים תפקיד ומדביקים את הקוד המתאים: מנהל לפי השדה reviewer, ואיש מכירות לפי השדה analyst.

**המודל בהרצה מקומית:** בלי מפתח OpenRouter, המערכת פונה ישירות לאולמה במחשב שלכם. צריך שאולמה ירוץ ושהמודל יהיה מותקן:
```bash
ollama pull gemma4:latest
```
אפשר לבחור מודל אחר בעזרת משתנה הסביבה
`OLLAMA_MODEL`

הנתונים נשמרים בתיקייה `data/` (מסד Postgres מובנה). מחיקת התיקייה מאפסת את הכול.

## בחירת המודל

מנהל בוחר את המודל במסך **"חיבור מודל"**. ההגדרה משותפת לכל המשתמשים.

**OpenRouter, מודלים חינמיים בלבד**
- המערכת בוחרת אוטומטית מודל חינמי מתאים, ומנסה עד שלושה אם אחד לא עונה.
- מותר רק מודל ששמו מסתיים ב-`:free`, וכל בקשה נשלחת עם תקרת מחיר אפס. אין אפשרות לחיוב.
- במסלול החינמי יש מגבלה של 50 בקשות ביום למפתח.

**אולמה של הצוות, דרך גשר**
צוות שרוצה שהמערכת בענן תשתמש במודל שרץ אצלו:
1. מתקינים אולמה ומודל, Node בגרסה 18 ומעלה, ו-cloudflared.
2. מורידים מתיקיית `bridge/` את שלושת הקבצים (הם זמינים גם להורדה מתוך מסך "חיבור מודל").
3. מריצים בווינדוס:
   ```
   bridge\start-bridge.ps1
   ```
   או במק ולינוקס:
   ```
   bridge/start-bridge.sh
   ```
4. הסקריפט מדפיס כתובת https ומפתח. מדביקים אותם במסך "חיבור מודל", שומרים ולוחצים "בדוק חיבור".

הגשר מקבל רק בקשות צ׳אט שנושאות את המפתח, ולא חושף שום דבר אחר במחשב. השרת דוחה כתובת גשר שמפנה לרשת פנימית.

## פריסה עצמאית בענן

כדי להרים עותק משלכם צריך חשבון ב-Vercel, מסד נתונים ב-Neon (יש מסלול חינמי) ומפתח OpenRouter (אופציונלי).

משתני הסביבה בפרויקט ה-Vercel:

| משתנה | תפקיד |
|---|---|
| `DATABASE_URL` | כתובת החיבור ל-Postgres של Neon |
| `VAULT_KEY` | מפתח הצפנה: 32 בתים אקראיים בקידוד base64. **מי שמאבד אותו לא יוכל לקרוא את הנתונים** |
| `ALLOWED_HOSTS` | שם המארח של האתר, למשל `my-app.vercel.app` |
| `WEBHOOK_KEY` | סוד לכניסת ה-Webhook |
| `OPENROUTER_API_KEY` | אופציונלי. בלעדיו המערכת עובדת רק דרך גשר אולמה |
| `LLM_PROVIDER` | `openrouter` או `ollama` (ברירת המחדל: openrouter) |

יצירת מפתח הצפנה:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

פריסה:
```bash
vercel --prod
```

יצירת קודי גישה אישיים (למשל 5 מנהלים ו-5 אנשי מכירות). הקודים נכתבים לקובץ `ACCESS-CODES.txt`, שלא עולה לגיט:
```bash
node --env-file=.env.production.local scripts/accounts.mjs 5 5
```

## אבטחה

- הצפנת AES-256-GCM לשדות רגישים: שיחות, ידע, טיוטות, ראיות וצילומים.
- שרשרת HMAC על לוג האירועים, כדי לזהות כל שינוי ברשומות.
- הרשאות לפי תפקיד, CSRF, CSP, עוגיות HttpOnly ו-Secure, והגבלת קצב.
- הסרת דוא״ל, טלפון וסודות מההערות לפני שהן נשלחות למודל.
- ניסיון הזרקה מחשבון ארגוני גורם לחסימה, להסגר החשבון, לצילום מוצפן ולהתראה שעולה דרגה כל 60 שניות.
- קודי הגישה לא נשמרים כטקסט: במסד נשמר רק HMAC שלהם.

**מה עוד לא קיים:** כניסה ארגונית (SSO/MFA), ניהול מפתחות ב-KMS, בדיקת חדירה עצמאית ושליחת התראות לדואר או לסלאק. לא מובטחת חסינות מכל תקיפה. פירוט מלא נמצא ב-`docs/security-report.md`.

## מבנה הפרויקט

```
api/index.mjs        נקודת הכניסה בוורסל
lib/app.mjs          השרת: תהליכים, כלים, אישורים, אבטחה, לוגים
lib/db.mjs           שכבת Postgres (Neon בענן, PGlite מקומית ובבדיקות)
lib/llm.mjs          OpenRouter חינמי וגשר אולמה
security.mjs         הצפנה, חתימות, זיהוי הזרקות
system-prompt.txt    הנחיית המערכת למודל
tool-contracts.json  חוזי הכלים
seed.json            בסיס ידע לדוגמה (נתונים בדיוניים)
public/              הממשק
bridge/              גשר אולמה לצוותים
scripts/accounts.mjs יצירת קודי גישה אישיים
tests/               בדיקות מקצה לקצה
docs/                מסמכי ההגשה המקוריים
```

המסמכים בתיקייה `docs/` נכתבו לגרסה הראשונה של המערכת, שרצה על מחשב מקומי עם מנהרה. הארכיטקטורה המעודכנת מתוארת בקובץ הזה.
